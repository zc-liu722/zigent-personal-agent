# 本地交互工坊

在开发检出目录执行：

```sh
npm run dev:components
```

打开 `http://127.0.0.1:4317`。需要现有的 Node、npm 依赖和 Git；不需要启动 Agent 或登录生产账号。内置聊天通过本机 Codex 执行，GPT 复用 `codex login` 的 ChatGPT 登录；Kimi Code 复用本地环境或 `.env` 中现有的 `KIMI_CODE_API_KEY`，也可用 `COMPONENT_STUDIO_KIMI_CODE_API_KEY` 单独指定。配置密钥后重启工作台，点击“连接模型”。端口可用 `COMPONENT_STUDIO_PORT` 和 `COMPONENT_STUDIO_PREVIEW_PORT` 配置，两个服务都只监听 `127.0.0.1`。

## 人工与 AI 的迭代流程

1. 选择场景。左列显示当前真实源码，右列显示该场景草稿叠加到当前源码后的效果。两边使用相同的状态、主题、视口和模拟响应；可分别点击真实组件。Mock 数据来自各版本的 `components/fixtures.js`，包含子 Agent 协作、状态分组、展开任务/执行过程/结果、延迟加载失败和重试。
2. 在页面的 GPT / KIMI 对话区选择模型、思考强度并发送修改要求。当前页面与对话固定绑定到同一组件草稿；Codex 可读取该组件代码及左右预览的可见文字、控件、尺寸、样式，直接修改草稿并编译检查。每个组件有独立的聊天记录；切页不改变已发送请求的目标。模型及思考偏好按组件、模型保留，每轮发送时固定。切换模型或思考强度时，新建执行线程，仅带入本组件已显示的对话；不沿用另一模型的内部状态。也可点击“复制要求”，交给外部编码助手。
3. AI 保存文件后，通过文件监听和 SSE 自动更新右列。也可在“源码改动”直接修改 JS/CSS，点击“更新草稿”。这些操作只影响草稿。模型生成或合并期间暂停人工编辑和保存；点击撤销会先停止对应组件的生成，再丢弃草稿。
4. 点击“保存此项”或“全部保存”，将草稿真实写入仓库 `web/`。这些改动立即可供本地开发加载，**保持未提交，不会自动执行 Git commit、push 或部署**。
5. “撤销此项/撤销全部”只丢弃未接受的草稿，重新从当前源码建立草稿；不撤销已经写入源码的改动。

工作台工具自身的开发仍按仓库默认 Git 发布规则交付；上述未提交约定针对人工在工作台接受的组件改动。

## 草稿、共享文件与冲突

每个已打开场景有独立的 `.runtime/component-studio/proposals/<id>/base/` 和 `draft/`。目录路径稳定，服务重启后保留草稿。同一检出只允许一个工作台进程；启动锁阻止第二个进程误恢复仍在进行的源码写入。`.runtime/` 已被 Git 忽略。

允许保存的文件是 `components/*.js`、`components/*.css`、`style.css`、`theme.css`、`dom.js`，支持新增、修改和删除。预览适配器 `component-preview.*` 及共享 Markdown/资源加载器是只读支撑文件，不属于候选组件改动。新增独立组件仍需通过正常源码维护同步资源登记及 mock 场景。

逐项保存以独立草稿为单位；修改共享渲染器或共享 CSS 会影响使用它们的所有场景。工作台按 `当前源码 / 草稿基线 / 草稿结果` 做三方合并：保留已存在及其他组件已接受的改动，互不重叠的修改可合并，重叠修改明确返回冲突。“全部保存”先合并和编译检查全部候选，任一冲突或语法错误都不会开始写入。

当前组件页发现源码冲突时，自动使用页面选择的模型与思考强度发起合并；正在进行的 AI 修改也会处理冲突。AI 必须读取当前源码、草稿基线和草稿，按三个版本的精确校验值提交合并结果；服务编译检查通过后，只更新该组件草稿及其合并基线元数据，原始快照和真实源码不变。用户只查看更新后的右侧效果并选择保存或撤销，无需编辑代码或点击“确认合并”。

同一冲突在多个窗口出现时不会重复发起模型任务。任务结束前再次检查合并结果；未通过时最多追加三次自动修复，仍失败则保留草稿并显示重试。停止或失败后，同一份冲突不会反复自动调用模型；可点击“AI 重新合并”重试，或撤销草稿。页面切换不会改变正在处理的组件。每次后续模型调用单独保留实际 token 用量，订阅金额仍为 0。AI 没有保存真实源码、提交或部署的权限。

保存同时校验页面所见草稿的版本及源码的当前内容，避免覆盖 AI 或其他窗口刚刚写入的文件。源码以同目录临时文件原子替换；多文件保存失败会回滚本次写入。如果同时出现第三方修改，保留恢复记录而不覆盖第三方内容。恢复记录位于 `.runtime/component-studio/transactions/`，服务启动时处理未完成的写入。没有 Git 索引、提交或远端操作。

## 本地服务边界

- 编辑服务（默认 `4317`）：本机 Host 校验、随机 HttpOnly/SameSite Cookie、同源写请求，文件写入严格限定组件文件。
- 预览服务（默认 `4318`）：独立来源，只提供只读 GET/HEAD；组件处于 sandbox iframe，不能操作编辑页面。
- 预览禁止网络连接和表单提交，授权、浏览器、Codex、下载等操作复用现有 mock 适配器；生成 HTML 仍在嵌套的不透明来源 iframe 里运行。
- 编辑服务启动独立的 Codex App Server，GPT 通过其官方认证流程复用 ChatGPT 登录；Kimi 通过环境变量向独立进程提供订阅密钥。模型和草稿工具无法读取登录缓存、凭据、生产配置、其他组件的聊天记录或 `.env`，页面和聊天记录不包含密钥。聊天记录保存在 Git 忽略的 `.runtime/component-studio/chats/`，服务重启后保留。
- Codex 使用只读线程，关闭 shell、MCP、应用、插件、联网和多 Agent；只允许工作台提供的上下文、文件读取、版本校验草稿修改、预览观察和编译工具。工具服务再次限定可写路径，Codex 没有保存真实源码、提交或部署入口。
- GPT 模型列表与思考强度取本机 Codex 的实时元数据；Kimi 列表、思考强度与上下文限额从 Kimi Code `/models` 目录读取，并匹配仓库目录中已有的 `kimicode` 订阅路由。只展示已登记的完整模型身份。供应方明确限额优先，目录缺失时不虚构可用模型；Kimi 不可用也不阻塞已登录的 GPT，反之亦然。订阅费用记为 0，保留供应方实际报告的输入、输出和缓存 token，缺失用量不补造。
- 上游重连时继续等待，提供手动停止；连接失败保留草稿和对话。协议依据 [Codex App Server 官方文档](https://learn.chatgpt.com/docs/app-server)。

## 文件

- `server.mjs`：两个本地 HTTP 服务、来源校验、SSE、输出 HTML 的只读包装。
- `kimi-provider.mjs`：Kimi Code 账户目录、运行时模型元数据与仅工作台线程生效的 Codex 自定义供应方；不修改全局 Codex 配置。
- `codex-chat.mjs`、`chat.js`：本机 Codex 连接、组件独立对话、流式回复、受限草稿工具和页面观察。
- `store.mjs`：草稿快照、三方合并、版本检查、源文件写回与恢复。
- `studio.html`、`studio.css`、`studio.js`：组件目录、双列效果、代码对照、人工操作。
- `preview-context.js`：从对应源码快照读取 mock 场景，接入正式 `web/component-preview.js`，保持左右两边运行真实组件代码。

可通过 `COMPONENT_STUDIO_CODEX_COMMAND` 指定本机 Codex 可执行文件；默认优先复用 Mac 桌面应用内置版本，其余环境使用 PATH 中的 `codex`。此入口仅存在于本地工作台，生产 Dashboard 的组件预览仍为只读展示。

Kimi Code 接入遵循[官方 Codex 配置说明](https://www.kimi.com/code/docs/third-party-tools/codex.html)，使用原生 Responses。工作台在 `.runtime/component-studio/` 生成不含密钥的模型元数据文件，不改写 `~/.codex/config.toml` 或系统模型默认值。当前接入仓库已登记的 `kimi-k3.1pro-kimicode`、`kimi-k3.1prohighspeed-kimicode`、`kimi-k3-kimicode`。
