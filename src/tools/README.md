# 工具开发与“脑海”展示

工具展示是工具契约的一部分。新增本地工具时，需要在同一个 `AgentToolRegistration` 中同时提供：

1. `definition`：模型可见的工具名称和输入 schema。
2. `execute`：真实执行逻辑和原始输出。
3. `activity`：把真实输入、输出和错误翻译成用户可见的活动。

最小结构：

```ts
const activity: ToolActivityPresenter = {
  started: (input) => ({
    message: "我正在查找相关记录。",
    details: [{ label: "查找内容", value: readQuery(input) }]
  }),
  completed: (_input, result) => ({
    message: "相关记录已经找到了。",
    resources: readResources(result),
    resourcesLabel: "相关记录"
  }),
  failed: (input, error) => ({
    message: "这次查找没有顺利完成。",
    details: [
      { label: "查找内容", value: readQuery(input) },
      { label: "原因", value: error }
    ]
  })
};

return { definition, activity, execute };
```

`ToolActivityPresentation` 只接受以下渠道无关字段：

- `message`：必填，第一人称、面向用户的当前动作或结果。
- 技能操作的标题与各阶段消息包含校验后的技能名，例如“查看技能 health”“加载技能 cpo”“查看技能修订 health”；不展示私人正文或规则。普通命令明确读取 `<技能名>/SKILL.md` 时也展示技能名，包括对 `$env:ZIGENT_SKILLS` 的字面量读取；混合脚本不猜测。
- `title`：可选，简短的“动作 + 对象”，用于网页单行工具展示。动作在各阶段保持一致，取得明确的对象名称后可补全标题。仅使用白名单字段，例如文件名或文档标题。
- `actionKind`：可选，说明多用途工具此次执行的是搜索、阅读、编辑、查看图片、待办或等待。网页用它选择图标。
- `command`：可选，仅从 `exec_command.cmd` 选取的实际 Shell 命令，最多 64,000 字符；标题使用首个非空行，网页默认折叠为首行并可展开完整命令。其余参数、stdin 和原始日志不进入该字段。
- `fileOperation`：可选，明确的 `read`／`edit` 操作，网页使用阅读／编辑图标及单行文件摘要，展开查看文件列表与操作详情。覆盖文档和项目资料读取、文档创建／编辑／移动、补丁文件头及可明确识别的 Shell 文件读写；未知程序、混合运行或脚本命令保留终端展示。仅提取文件名／路径，不将补丁正文、文档正文或搜索表达式用作文件摘要。
- `diff`：可选，仅用于用户要求的文件编辑差异，包含 `patch` 及可确认的 `additions`／`deletions`。补丁展示实际输入中的增删行；删除文件时尝试读取该文件的旧文本，缺失时不虚构计数。直接创建／编辑文字文件从本次写入前后的文本生成统一差异。摘要末显示绿色 `+`／红色 `−` 行数，展开按行着色并可复制；完整差异延迟加载，折叠历史只保留计数。差异元数据不进入模型的工具结果，不包含无关文档正文或原始日志。
- `details`：可选的标签和值；长提示词可使用 `format: "quote"`。
- `resources`：可选的资源标题、HTTP(S) 链接和简短说明。
- `resourcesLabel`：可选的资源分组名称。
- `hidden`：仅用于没有用户价值的内部步骤。
- `waiting`：可选，表示所等待的工作仍在进行；单次等待窗口结束仍显示“等待”，不视为失败。收到状态或操作失败时显式设为 `false`。

展示规则：

- 只挑选有助于用户理解进度的字段，使用明确的字段白名单。
- 不返回原始 JSON，不展示凭据、Token、Cookie、二进制、长正文或内部控制字段。
- `completed` 和 `failed` 会与 `started` 的展示信息合并，因此可以只补充发生变化的文案、资源或错误。
- 单条文本会被限制为 4,000 字，资源最多展示 8 个；不要依赖截断代替主动筛选。
- 内置供应商工具需要在 `registry.ts` 的 hosted presenter 映射中提供同样的三阶段翻译。

接入链路无需由新工具重复实现：执行器调用 `presentActivity` 产生 `AgentEvent`，`AgentTranscript` 合并为 `AgentActivityItem.presentation`，通讯渠道只读取这些固定字段渲染。完整原始输入输出与翻译后的活动通过宿主 ConversationStore 保存不可变引用；兼容读取视图继续提供 `tool_trace_json` 与 `activity_trace_json`，不在多个位置重复保存正文。

新增工具需审阅代表性输入、成功输出、失败输出，以及敏感或冗长字段是否进入展示结果；遵循仓库快速迭代约定，不新增自动化测试。TypeScript 和运行时注册都会拒绝缺少 `activity` 的本地工具。

## 通用能力与项目

本地注册可通过 `resultFailed(result)` 将正常返回中的失败标为 tool.failed，仍保留原始结果、输出和 session 给模型。命令工具据非零 exit_code、执行失败或工作区保存错误判断；不能仅依靠 execute 是否抛异常。

网页账号连接通过渠道提供的 `authorizeAccount` 等待凭据保存与连接验证，然后续接当前工具调用；支持 Notion、XMind、Google Calendar、Google Drive、Todoist 和飞书文档。授权链接与凭据只经认证操作区传输，不进入模型记录。用户停止或替换原回复时取消等待，账号登录本身仍可完成；不跨服务重启重放操作，也不重做此前成功的调用。写入继续经过原有确认流程。后台任务不发起或等待交互授权，不支持续接的其他渠道才返回 `authorization_pending`。

飞书文档、搜索和纪要读取按默认顺序尝试已授权账号，区分文档访问、应用权限和令牌错误。没有可用授权时用标准卡片继续；应用缺少权限时更新原应用。已有账号均无权访问时，卡片提供重试原读取和切换账号。切换由用户明确发起，重复提交复用当前卡片；链接打开、等待授权和重试原读取分别显示进度。账号验证通过后，工具使用原参数重试读取，成功才恢复模型；失败在同一卡片显示原因并结束本轮。独立检查账号连接只更新卡片。写入继续使用原确认路径。

文件与编程使用 `exec_command`、`write_stdin`、`apply_patch` 和 `view_image`。harness 按文件归属或已选项目解析环境，普通会话首次执行时分配目录。`files` 按附件、成果版本或所属环境直接读取文件，程序需要路径时才导入。`artifact_files` 保存和交付不可变成果。详情见 [文件与编程底座](../../docs/ARCHITECTURE.md)。

`image_assets` 统一公开网页图片发现、原图读取、浏览器元素截图和工作区图片的正文交付。`inspect` 供模型查看像素并返回当前回复的临时 assetId。`present` 使用唯一已发送段落作为 after，把选中的快照和待交付记录持久保存，重试沿用原回复、位置和图片。正文、HTTP/SSE、刷新和历史读取使用同一个 image 输出块，来源链接与截图身份随快照保留。试裁图和转换中间文件使用 `exec_command cache=render` 的目录；最终文件持久交付且执行、同步结束后才清理；原件、重要文件和最终版本不能放入该目录。新工具在本地与生产 Agent 清单同步启用，子 Agent 和未授权后台任务不可直接交付图片。

项目选择只改变会话默认执行位置。`exit` 清除默认项目，显式文件编号仍按原归属解析。归属不明确的项目任务沿用经过认证的项目选择组件；取消后原选择保留，不自动执行该项目写入。

能力与项目分层：PDF／Word 读取、页图与检索是 `src/capabilities/documents/` 中的通用能力，工具定义维护用法。独立 `documents` 工具接收用户已分享的上传文档、确认导入的具体服务器文件，以及可选的已授权项目来源；无需先登记项目。旧 `project_files` 已退役，登记项目通过普通工作区原目录绑定，由 `exec_command`、`apply_patch`、`view_image` 读写。本地文件导入走现有认证网页确认路径，读正文前展示确切文件路径，工具参数不能伪造点击授权。项目条目只维护业务背景、用户角色和资料入口，加载项目时提供已授权工作区编号和当前资料入口。架构、定位、覆盖限制与调研依据见[文档能力](../../docs/ARCHITECTURE.md)。

`documents` 另提供 `create_text`、`edit_text`、`move_file`，在已有文件授权内直接创建项目文档、编辑网页文字附件／项目文字、将附件移入项目或调整项目文件位置，无需 Codex 派发。附件旧版和归档位置持久保存，下载按内容摘要重新验证缓存。编辑与移动要求具体文件 SHA-256；项目清单摘要不能代替文件摘要。精确替换只接受原版中唯一且互不重叠的匹配；目标同名异内容拒绝覆盖，部分移动明确返回目标与保留的来源。后台工具权限和额外服务器文件的导入确认保持原有机制。

Codex 分工不能缩减用户目标，不能擅加离线降级、产出格式或额外限制。原始用户要求由对话通道逐字保存并随任务交给执行器；确认卡片分别展示原话、分工和完成核对授权。显式授权核对的任务结束后进入持久审阅，按原目标决定交付、同会话补做或请用户决策；补做保持原范围和授权时间，取消、范围变化及失效回执不得触发新任务。

技能使用 `skills list/load/updates` 发现、加载和查看修订。托管 Markdown 通过 `markdown list/read/search/edit` 管理。确认后由所属存储检查版本并保存，普通技能和健康技能继续各自校验权限。详见 [技能管理](../../docs/ARCHITECTURE.md)。

主动任务和健康后台通过 `AgentInteractionController.prepareBackgroundRun` 在执行前注册真实的任务会话、固定运行关联，并调用普通回复的同一个 `workspaceContext` 组装入口；不伪造用户消息。技能目录、按需加载、项目状态、执行环境和附件/会议领域上下文复用相同服务，触发数据和任务指令单独提供。新会话仍按普通会话规则选择项目和加载技能，不继承任意最近会话的项目。有效的任务租约允许任务范围内的文件读取、研究归档和文件交付；每次调用继续核对 Agent、所有者、会话及租约，过期、取消、修订或撤权后拒绝调用。后台没有交互授权或变更确认回调，账号连接、对外写入、技能维护、用户安排和任务管理继续受各自权限约束。

登记配置中的 `description/introduction` 只为尚无持久记录的 skill 提供初始内容；启动时把原项目说明及有效会话加载标记迁入统一存储，已有修改和删除墓碑不被发布覆盖。每轮只提供名称与简短用途目录，`skills load` 后才在当前会话持续提供最新正文。`read` 和 `workspaces select` 不激活；新会话重新加载，旧会话跨重启保留加载状态。目录绑定与同步设置仍由项目登记管理，文件继续使用普通文件工具按需读取。

同一份技能文档的精确替换与追加基于同一原版。记忆文档可在一个代次合并确认；跨记忆与技能的变更分开确认。历史待确认卡片仍沿用原参数与幂等凭证。

## 主动规则维护

`phone_notifications` 提供 owner 私聊的通知接收状态、按时间/App/中文子串分页检索及单条原文读取；有效主动任务租约允许只读访问，健康后台和其他身份不可访问。通知来自已有设备事件入口，历史补传只入库，不影响触发点与近期事件条件；文本不授予工具执行或记忆写入权限。活动展示只报告动作与数量，不展示通知、关键词或凭证。接口、存储及生产接入见[手机通知](../../docs/ARCHITECTURE.md)。

`create` / `propose` 的 `title`、`instruction`、`trigger` 必须放在顶层；`spec` / `fixtures` 仅用于 `trigger_stage`，不能包裹任务。提议与执行共用 `proactive-task-input.ts` 的纯校验，无效参数必须在展示确认组件前返回给模型。定位事件叠加工作日/时段条件时，先暂存并验证规则，再用 `trigger={type:reference,triggerId}` 与 `activate_revision` 提议同时启用规则和创建任务。

可复用触发规则继续使用 `proactive_tasks`，不新增通用代码执行或文件写入工具。`trigger_list`、`trigger_stage`、`trigger_validate` 不启用规则；`trigger_activate`、`trigger_rollback`、`trigger_pause`、`trigger_resume` 走共享操作确认。规则来源、条件、取消事件和正反例必须通过后端严格 schema 校验，测试调用真实求值器，不调用模型或发送消息。修改、启用和恢复时保留 owner/principal 与来源授权，后台执行禁止管理规则。

为减少每轮工具上下文，可复用规则的模型可见条件 schema 在各层共享字段形状，条件类型的必填字段、互斥字段、时间格式和数值范围由 `parseReusableTriggerSpec` 的严格判别联合统一校验；精简模型 schema 不得替代或放宽后端校验。保留各条件类型、字段和原有嵌套深度，且不依赖供应商未确认支持的递归 JSON Schema 引用。

确认前读取完整目标修订和订阅影响范围，确认时比较同一份保存状态；运行游标和最近事件不得使无关的用户确认过期。规则修订号、内容摘要和验证记录属于判断依据，不能在确认后悄悄替换。活动展示只报告维护动作和验证结果，不输出事件载荷、测试内容、身份、凭据或内部确认编号。扩展和发布边界见[主动任务架构](../../docs/ARCHITECTURE.md)。

## 长期记忆与存档记忆

`markdown` 提供私人档案、共享规则和专题档案的逻辑文档标识。后台主动任务仅在有效执行授权内读取。详情见 [记忆](../../docs/ARCHITECTURE.md)。

派发前按语义核对用户意图：允许模型改写、综合跨会话需求、拆解任务并补充合理执行细节，不要求字面匹配。模型先检索相关历史，使用 sourceTurns 引用原始用户轮次；服务端验证所属用户并重新读取原文，和当前要求、相关偏好一起核对是否有目标漂移或擅加限制。经核对的需求依据随确认卡片和任务持久化，供执行与完成审阅使用；最近几条原话只是起点，不是意图范围。用户直接编辑卡片可补充或修订要求。

## 动态工具描述刷新

私有健康工具的描述和输入 schema 按会话授权及 health 加载状态投影。Codex 的 dynamicTools 在 thread/start 时固定，技能加载成功不会修改既有线程的描述。执行器发现工具目录扩展或阶段变化后，先保存成功调用和结果，再通过 refreshTools 请求适配器立即停止旧线程；新调用重新投影完整工具目录，带回已保存结果。旧目录不能继续执行后续调用，加载动作不重放。不等旧线程自行完成回答才刷新，也不通过源码阅读代替能力发现。

## 子 agent

`subagents` 在当前用户轮次内派发独立子任务，提供 spawn/list/wait/read/continue/cancel。每次 spawn 必须提供具体英文人名、职业身份、任务标题和任务内容，前端按“英文人名 + 职业身份”展示。`name` 按职业选择领域顶尖人物的英文姓名，可以使用知名专家或名人的姓名，不使用固定人名名单，不接受职业、角色、主题或任务名；任务名填写在 `title`，职业填写在 `profession`。`spawn` 可选传 `model`，仅接受当前 Agent 已配置的完整模型身份，工具 schema 枚举同步提供可选值；省略时继承主任务派发当下的实际模型，续派保留子模型。思考偏好按所选模型读取本轮快照或其自身默认值。调度器由 AgentExecutor 注入可信上下文，工具参数不接受用户、Agent 或会话覆盖。沿用父权限和确认路径，同时最多运行 3 个子任务，不设累计子身份数、续派次数、工具调用、模型轮次或总运行时间预算；父任务共享执行器同样不设工具调用与模型轮次预算。取消和父轮次结束仍正常收尾；共享工作区显式寻址，子任务不递归派发、不操作共享浏览器、不直接交付。源码研究、适用判断、持久记录及发布边界见[子 agent 派发](../../docs/ARCHITECTURE.md)。

## 浏览器与调研的工具选择

浏览器仅用于必要的网站交互（登录、表单、上传）、其他工具无法取得的视觉/动态内容，或用户明确要求使用浏览器。优先使用专用工具/API；公开调研使用 `web_search` 和非浏览器读取，搜索不足不自动转用浏览器。用途边界集中维护在浏览器工具描述中，避免共享提示重复。

旧 `update_skill` 待确认卡仅在服务端确认处理时映射为 `skills`：卡片内容、按钮摘要、基线和幂等键保持原样，仍须真实用户点击并重新核对；不把旧名注册成模型可调用的别名。后台 `skills` 只提供 `list/read/load/updates`，执行层同样拒绝写入。

`gmail` 使用独立授权，搜索/正文/附件读取和发送/回复通过现有 Google 网页连接与操作确认链路。发送先展示实际账号、全部收件人和附件版本，确认时核对摘要；持久发送记录阻止不确定结果自动重发。活动三阶段仅使用固定动作文案。配置及限制见 [Gmail](../../docs/ARCHITECTURE.md)。

## 日历改期与确认回执

`google_calendar` 在准备阶段校验输入；更新可只提供 `start` 或 `end`，另一端保留。预览和执行共享 `calendarChangeBody`，按已读日程核对完整时间范围，不再让只改开始时间的卡片在点击后才因缺少结束时间失败。

修改和删除以已确认的事件 `ETag` / `If-Match` 写入。回执不确定时自动回读：所请求字段已符合即确认成功，版本变化则停止；仍为原版本时最多重试一次，始终使用原 ETag，避免重复提交或覆盖后续编辑。无法核实时保留未知，不把暂时未变化视为原请求不会晚到。诊断只保存固定原因与 `not_applied` / `conflict` / `uncertain` 结果类别。协议依据：[Google 资源版本](https://developers.google.com/workspace/calendar/api/guides/version-resources)。

手机离线点击提示联网后重试，不保存离线操作队列。点击立即显示提交中，最多等待回执 12 秒；HTTP 202 只表示接收，完成状态由认证 HTTP 刷新和 SSE 更新。断线、超时、响应损坏或网关故障显示结果待核实并读取状态，允许同一卡片、同一动作 ID 核对重试；服务端执行锁、原子占用与版本基线阻止重复执行。重连与页面恢复沿用会话同步。


普通原生命令采用按会话的 64 个句柄软上限，不共用每 Agent 两个任务的硬名额。
`yield_time_ms` 只限制等待回复的时间；未显式设置 `timeout_ms` 的原生终端不设
生命周期时限。空轮询至少等待 5 秒、最多 5 分钟，Windows 初始等待至少 10 秒。
输出默认 10000 tokens、每次最多 1 MiB，剩余输出通过原 `session_id` 继续读取。
命令、stdin 与补丁的活动展示继续覆盖开始、完成、失败，且不输出 stdin 正文。
请求排队、控制通道及软上限回收见 `ops/execution/README.md`，持久日志和私人内容不因句柄回收删除。
