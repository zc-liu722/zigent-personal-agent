# 会话交互组件与预览台

入口：服务监控 → **交互组件**（`/dashboard/#components`）。沿用 Dashboard 管理登录。

本地代码迭代使用 `npm run dev:components`，打开 `http://127.0.0.1:4317`。支持当前源码/修改草稿的双列对照、文件自动刷新、逐项或全部保存/撤销，保存写入真实源码并保持未提交。详见 [本地交互工坊](../../ops/component-studio/README.md)。

## 明暗主题颜色盘点（2026-11-01）

| 范围 | 盘点与处理 |
| --- | --- |
| 公共交互卡片、业务预览标题 | 两层标题样式原为固定黑色，统一使用 `--ink`；覆盖账号连接、确认、任务、记忆、日历、待办、脑图和文档等共用卡片。 |
| 日历事件、Todo 内容标题 | 各自独立的固定黑色改为 `--ink`，保留字体与排版。 |
| 文档差异标题、文件历史 | 移除未定义的 `--text-secondary` / `--ui-text-secondary` 及固定灰色回退，使用现有 `--muted`。 |
| 确认完成、Todo 删除、Codex 失败状态 | 补齐明暗配色；删除标记与删除线共用同一个状态色。 |
| 隔离可视化与动画内部 | 补充 SVG 默认填色、旧内容固定中性色和 Canvas 绘图颜色解析；按 `data-theme` 提供具体颜色值，主题变化时重建画布并恢复控件、播放进度。旧成果在重新加载后使用新运行时，无需修改保存的对话内容。 |
| 问答、模型选择、任务与触发器、地图、脑图、表格、资源、记忆差异、过程与子 Agent | 已使用主题变量或有对应深色覆盖；未发现其他固定黑色文字。 |

新增文字颜色优先使用 `--ink`、`--muted`、`--accent`；业务状态和插图配色需要同时考虑两种主题。图表序列、遮罩的黑色、阴影和头像眼睛等图形颜色不属于正文文字，不做机械替换。以上为源码与样式层叠盘点，未运行浏览器视觉检查。

## 会话输出配色

- 卡片指标可用 `tone: "support"` 标出对照指标，或用 `tone: "detail"` 标出一个重点数值。
- 原生图表与交互画布及 Mermaid 共用 `--ui-series-1` 至 `--ui-series-12`。前 3 个系列依次使用主强调色、衬托色、点缀色。原生折线图和柱状图可用 `highlight: { seriesIndex, pointIndex }` 标出单个关键数据点，两个索引都从 0 开始。
- Mermaid 流程图可通过 `:::support` 标记旁支节点，或通过 `:::detail` 标记一个重点节点。配色插件负责填充和边框。未指定用途的节点使用主题默认样式。
- 隔离画布使用 `--ui-bg`、`--ui-surface`、`--ui-text`、`--ui-muted`、`--ui-soft`、`--ui-accent`、`--ui-support`、`--ui-detail`。线条可用 `--ui-line`，主强调色上的文字可用 `--ui-on-accent`。Canvas 用 `window.zigentTheme.color('var(--ui-support)')` 获取解析后的颜色。

隔离画布的兼容层适配旧作品中的近黑和近白中性色，保留作者指定的分类色和图片。切换主题时，宿主恢复已记录的控件状态和动画时间。

## 代码入口

- `web/components/index.js`：共享模块入口；会话和预览台都从这里创建交互渲染器。
- `web/components/subagent-view.js`、`activity-renderer.js`：子 Agent 面板与思考/工具过程的真实共享渲染器，普通会话与两个预览台复用。
- `web/components/interaction.css`：从全局 `style.css` 提取的卡片、问答、模型、任务及 Codex 样式。
- `web/components/operation-preview.js`：五种业务预览的统一分发。
- `web/components/fixtures.js`：只包含展示数据；增补场景在这里维护。
- `src/web/component-assets.ts`：会话与 Dashboard 共用的静态资源注册表；保留旧资源 URL 兼容入口。
- `web/component-lab.js`：场景目录、JSON 编辑、状态/宽度/主题/响应控制、操作记录。
- `web/component-preview.*`：独立预览文档和 mock 适配器。

页面布局、消息定位和 HTTP/SSE 连接仍由会话页面负责；服务端协议和实际操作继续位于 `src/web/interactions.ts`、各业务服务及已认证路由。全局颜色在 [配色插件](../plugins/palette/colors.css) 维护。日历、自动任务、文档编辑器、文件工作台、浏览器工作台属于完整业务页面，不复制进卡片预览；预览台展示它们的会话入口，打开文档等操作使用 mock 内容并记录操作。

## 迭代与发布

预览台直接加载与会话相同的组件源文件，不维护第二份效果实现。桌面、平板、手机宽度改变 iframe 的真实视口，明暗主题仅作用于预览。JSON 编辑支持 `⌘/Ctrl + Enter` 应用；重置场景恢复默认数据。模拟响应可以选择成功、失败或延迟。

页面显示已加载的 BUILD；监控刷新发现不同部署版本时显示“载入 <版本>”，点击重新载入页面取得新版本模块和样式。版本表示正在部署运行的提交；本地开发展示本地代码，线上只有正常提交、推送、构建和部署完成后才更新。

预览文档要求 Dashboard 登录，禁止网络连接与表单提交，所有会话请求使用本地 mock 适配器，链接点击被拦截。`api/component-output` 只对已认证的 mock 输出做已有协议校验和 HTML 包装，不读取会话、不写入数据、不调用模型或第三方服务。生成的 HTML 在 `sandbox="allow-scripts"` 的不透明来源 iframe 中运行，继续使用真实交互输出的消息桥和生命周期。退出 Dashboard 会销毁预览。

发布打包分别保留原始组件资源和压缩后的 `shell-runtime.js`，避免预览台加载会话启动代码。新增组件时同步更新共享资源表和 mock 场景。

## 图像生成小游戏

等待卡片为高:宽 4:3 的纯画面，透明画布直接透出会话主背景，不另设底色或光晕。开场完整保持一秒向下流动的科技粒子，再滑入随机配色团子，随后约两秒逐渐淡出密集粒子、浮现可接光子；游戏期间保留 36 条清晰可辨的粒子流，提高常驻亮度与流线长度，用动效区分圆角区域。鼠标横移、整块画面的触摸点按/横拖或方向键控制小球；本体周围至少 96 CSS 像素的抓取区保留手指偏移，画面其他位置也可点按移动，手机竖向手势保留会话滚动。光子只做竖直运动，出生位置避开团子当前及目标位置的本体投影；每颗光子还记录出生时的输入移动量，必须在出生后有横向操作才可接取，静置不会自动成长。团子边长从 64 开始，每颗光子增加 2.6，单关上限 128；所有下落物的即时速度乘以当前边长与初始边长之比的平方，首关为约 0.47–4 倍，跨关难度平缓增长并封顶为额外 1.25 倍。

开场后开始落箭，按明暗主题预绘冷色珠光细轴、双侧尾羽与刻线、分面箭头、淡玫瑰色锋线与红色尖端涂层。随着团子变大，提高每批期望数量与频率，但安全间距优先：任意两支箭尖在 280 个逻辑像素高度带内时，横向中心距离必须大于 164（本关最大团子边长 128 + 箭头宽度 12 + 余量 24），间隙始终宽于小球。检查覆盖同批及此前仍在场的箭；有限次采样无解就跳过该支，不强行生成。当关可造成伤害的箭使用相同基础速度 88 和共享体积/关卡倍率，不会因追赶破坏间距，每个保护高度带最多容纳两支危险箭。箭尖与团子本体做相对运动扫掠碰撞，命中后边长持续缩小 18%（最低 44），只保留委屈表情与泪滴，不显示创可贴；短暂保护避免连续反馈。接光子恢复表情并逐步长回体积，静置不会自动恢复体积，无生命值、倒计时或游戏结束。生成工具完成、失败或取消时沿用真实消息状态移除画面，不阻塞图片交付。

团子长满后进入 1.8 秒的五次平滑镜头拉远：本体与完整旧场景等比例缩至一半，旧粒子、光子、箭、光滴和波纹始终保留，不做换关淡出或清屏。事先在原视野外的上、下、左、右空间铺入粒子，由同一镜头自然揭露；粒子色彩保持一致，短暂显示下一关编号。过渡期间停止生成和伤害，保留触控；结束时把全部元素的位置、尺寸、线宽与速度按最终缩放归一化，团子恢复 64，下一帧接续同一幅画面。旧光子继续可接，远处旧箭保留轨迹并在换关保护中自然落出；新箭继续遵守完整安全间距。旧粒子移出视野后回收，连续四次拉远后仅剩 0.05 逻辑像素线宽的细节可复用。此过程无关卡上限，使用固定粒子池，不累积世界坐标或无限提高速度。减少动态效果偏好直接进入下一关。

`mochi.js` 的轮廓和五官由游戏与子 Agent 共用，每轮等待随机选择一种柔和色相，各表情共用该色；子 Agent 在首次出现时随机配色，此后保持身份颜色。Canvas 使用共享 30fps 时钟、最多 96 条开场粒子（过渡后 36 条常驻），固定 192 槽粒子池容纳每次新揭露的 36 条粒子及保留的旧场景、24 颗光子、最多 16 支箭和 24 颗反馈粒子；流线分批绘制，光晕/箭共用预绘缓存，团子各表情按本轮颜色预绘制，最多 2 倍像素密度。离屏及后台暂停，消息移除/切换会话时释放帧回调、监听器、观察器及画布。减少动态效果偏好跳过密集开场与过渡，关闭弹性/震动/手势提示，并降低光子密度。

团子定位在距画面底部 26 个逻辑像素的基线上，只保留小球本体，不绘制滑板与板下阴影。光子与箭均按团子本体做相对运动扫掠碰撞，接取范围随体积变化。漏接光子按实际 CSS 圆角半径计算地板与底部圆角碰撞，沿内法线溅出小光滴和半环波纹；散落光滴再次落地时消散，永不触发接取或成长。复用光子的预绘光晕，光滴池最多 48 颗、波纹池最多 8 个，整个画面共用精确圆角裁切。

## 睡眠展示发布边界

睡眠图的绘制、文字、样式和点按/键盘交互位于 `web/components/sleep-timeline.js`、`sleep-timeline.css`，随不可变 web 资源集独立发布。后续仅修改这些文件会归为 `web`，不要求宿主重启；已打开的页面保留原资源版本，刷新后使用新版本。

后端附件通过 `data: { type: "sleep-timeline", version: 1, start, segments }` 传递受限的纯数据。`start` 是毫秒时间戳，分段为相对毫秒 `[start, end, stage]`；来源选择、空档、冲突和睡眠统计语义仍由健康数据流程负责。既有 `output` 保留简短 HTML 文字摘要，让尚未刷新的旧客户端继续可读。未知数据版本退回摘要，不执行数据。新客户端仅为服务端程序附件启用原生组件，不改变模型生成 HTML 的沙箱隔离。

旧睡眠附件由前端从已保存 HTML 的固定 JSON 声明中提取分段并校验，不挂载或运行原脚本，也不重新读取健康数据库。`fixtures.js` 的“睡眠时间线”沿用同一组件。协议与后端数据生成变更仍走宿主发布；本次迁移也需要一次受控宿主升级，不能通过放宽发布输入分类规避。
