# 会话交互组件与预览台

入口：服务监控 → **交互组件**（`/dashboard/#components`）。沿用 Dashboard 管理登录。

本地代码迭代使用 `npm run dev:components`，打开 `http://127.0.0.1:4317`。支持当前源码/修改草稿的双列对照、文件自动刷新、逐项或全部保存/撤销，保存写入真实源码并保持未提交。详见 [本地交互工坊](../../ops/component-studio/README.md)。

## 清点结果

改造前已有 `interaction-renderer.js` 作为卡片入口，但业务预览、结构化输出、触发可视化、样式分别散落在 `web/` 和 `style.css` 中。现在会话交互组件的实现、样式、mock 场景集中到 **`web/components/`**。

| 场景 | 显示与操作 | 主要实现 |
| --- | --- | --- |
| 账号连接 | 授权链接、复制链接、过期、重连 | `interaction-renderer.js` |
| 模型恢复 | 重试、切换模型、取消 | `interaction-renderer.js` |

| 主动任务 | 提议、计划、触发示意、逻辑图、启用/取消 | `interaction-renderer.js`、`trigger-*` |
| 日历与提醒 | 前后对比、时间与地点、提醒、确认/取消 | `operation-calendar.*` |

问答及其他卡片的公共状态包括待操作、完成、失败、过期、取消。`fixtures.js` 提供可切换场景；同一场景可切换状态和模拟响应，也可编辑 JSON。模型强度示例使用 `preview-v1-mock`，只描述 mock 控件，不是部署模型或供应商能力声明。

## 明暗主题颜色盘点（2026-11-01）

| 范围 | 盘点与处理 |
| --- | --- |
| 公共交互卡片、业务预览标题 | 两层标题样式原为固定黑色，统一使用 `--ink`；覆盖账号连接、确认、任务、记忆、日历、待办、脑图和文档等共用卡片。 |
| 日历事件、Todo 内容标题 | 各自独立的固定黑色改为 `--ink`，保留字体与排版。 |
| 文档差异标题、文件历史 | 移除未定义的 `--text-secondary` / `--ui-text-secondary` 及固定灰色回退，使用现有 `--muted`。 |
| 确认完成、Todo 删除、Codex 失败状态 | 补齐明暗配色；删除标记与删除线共用同一个状态色。 |
| 隔离可视化与动画内部 | 补充 SVG 默认填色、旧内容固定中性色和 Canvas 绘图颜色解析；按 `data-theme` 提供具体颜色值，主题变化时重建画布并恢复控件、播放进度。旧成果在重新加载后使用新运行时，无需修改保存的对话内容。 |
| 问答、模型选择、任务与触发器、地图、脑图、表格、资源、记忆差异、过程与子 Agent | 已使用主题变量或有对应深色覆盖；未发现其他固定黑色文字。 |

新增文字颜色优先使用 `--ink`、`--muted`、`--accent`；业务状态和插图配色需要同时考虑两种主题。图表序列、遮罩的黑色、阴影和头像眼睛等图形颜色不属于正文文字，不做机械替换。以上为源码与样式层叠盘点，未运行浏览器视觉检查。

隔离画布使用 `--ui-text`、`--ui-muted`、`--ui-line`、`--ui-bg`、`--ui-surface`、`--ui-accent`。Canvas 可用 `window.zigentTheme.color('var(--ui-text)')` 获取解析后的颜色；不直接把自定义属性的原始表达式交给绘图 API。兼容层只适配固定的近黑/近白中性色及其透明度，不反转图片或改写分类色；CSS、SVG 属性和动态插入节点均覆盖。动画由同一宿主时钟继续驱动，主题切换沿用已有控件和播放时间恢复机制；未纳入该机制的任意脚本内存状态不保证保留。

## 代码入口

- `web/components/index.js`：共享模块入口；会话和预览台都从这里创建交互渲染器。
- `web/components/subagent-view.js`、`activity-renderer.js`：子 Agent 面板与思考/工具过程的真实共享渲染器，普通会话与两个预览台复用。
- `web/components/interaction.css`：从全局 `style.css` 提取的卡片、问答、模型、任务及 Codex 样式。
- `web/components/operation-preview.js`：五种业务预览的统一分发。
- `web/components/fixtures.js`：只包含展示数据；增补场景在这里维护。
- `src/web/component-assets.ts`：会话与 Dashboard 共用的静态资源注册表；保留旧资源 URL 兼容入口。
- `web/component-lab.js`：场景目录、JSON 编辑、状态/宽度/主题/响应控制、操作记录。
- `web/component-preview.*`：独立预览文档和 mock 适配器。

页面布局、消息定位和 HTTP/SSE 连接仍由会话页面负责；服务端协议和实际操作继续位于 `src/web/interactions.ts`、各业务服务及已认证路由。`theme.css` 维护全站主题。日历、自动任务、文档编辑器、文件工作台、浏览器工作台属于完整业务页面，不复制进卡片预览；预览台展示它们的会话入口，打开文档等操作使用 mock 内容并记录操作。

## 迭代与发布

预览台直接加载与会话相同的组件源文件，不维护第二份效果实现。桌面、平板、手机宽度改变 iframe 的真实视口，明暗主题仅作用于预览。JSON 编辑支持 `⌘/Ctrl + Enter` 应用；重置场景恢复默认数据。模拟响应可以选择成功、失败或延迟。

页面显示已加载的 BUILD；监控刷新发现不同部署版本时显示“载入 <版本>”，点击重新载入页面取得新版本模块和样式。版本表示正在部署运行的提交；本地开发展示本地代码，线上只有正常提交、推送、构建和部署完成后才更新。

预览文档要求 Dashboard 登录，禁止网络连接与表单提交，所有会话请求使用本地 mock 适配器，链接点击被拦截。`api/component-output` 只对已认证的 mock 输出做已有协议校验和 HTML 包装，不读取会话、不写入数据、不调用模型或第三方服务。生成的 HTML 在 `sandbox="allow-scripts"` 的不透明来源 iframe 中运行，继续使用真实交互输出的消息桥和生命周期。退出 Dashboard 会销毁预览。

发布打包分别保留原始组件资源和压缩后的 `shell-runtime.js`，避免预览台加载会话启动代码。新增组件时同步更新共享资源表和 mock 场景。

## 图像生成小游戏

等待卡片为高:宽 4:3 的纯画面，透明画布直接透出会话主背景，不另设底色或光晕。开场完整保持一秒向下流动的科技粒子，再滑入滑板与随机配色团子，随后约两秒逐渐淡出密集粒子、浮现可接光子；游戏期间保留 15 条隐约粒子流，用动效区分区域。鼠标横移、触摸横拖或方向键控制滑板，手机竖向手势保留会话滚动。光子只做竖直运动，出生位置避开滑板当前及目标位置的投影；每颗光子还记录出生时的输入移动量，必须在出生后有横向操作才可接取，静置不会自动成长。团子边长从 64 开始，每颗光子增加 2.6，上限 128；所有下落物的即时速度乘以当前边长与初始边长之比的平方，初始为 1 倍，最大约 4 倍，最小约 0.47 倍。

开场后开始落箭，按明暗主题预绘冷色珠光细轴、双侧尾羽与刻线、分面箭头及淡玫瑰色锋线。随着团子变大，每批从 1 支增至 4 支，间隔从约 3 秒缩短至约 0.8 秒；批内落点与高度错开，避免整排封路。箭尖与团子本体做相对运动扫掠碰撞，命中后边长持续缩小 18%（最低 44），只保留委屈表情与泪滴，不显示创可贴；短暂保护避免连续反馈。接光子恢复表情并逐步长回体积，静置不会自动恢复体积，无生命值、倒计时或游戏结束。生成工具完成、失败或取消时沿用真实消息状态移除画面，不阻塞图片交付。

`mochi.js` 的轮廓和五官由游戏与子 Agent 共用，每轮等待随机选择一种柔和色相，各表情共用该色；子 Agent 在首次出现时随机配色，此后保持身份颜色。Canvas 使用共享 30fps 时钟、最多 96 条开场粒子（过渡后仅更新 15 条）、24 颗光子、最多 16 支箭和 24 颗反馈粒子；流线分批绘制，光晕/箭共用预绘缓存，团子各表情按本轮颜色预绘制，最多 2 倍像素密度。离屏及后台暂停，消息移除/切换会话时释放帧回调、监听器、观察器及画布。减少动态效果偏好跳过密集开场与过渡，关闭弹性/震动/手势提示，并降低光子密度。
